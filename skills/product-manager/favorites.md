## 🔒 ОБЯЗАТЕЛЬНЫЕ скиллы (must-use, не предмет выбора)

Эти скиллы PM **должен включать в shortlist всегда** когда задача попадает в их зону. Не помечать как опциональные, не давать пользователю «вариант без них».

- **`anthropic-skills:ui-ux-pro-max`** — **ВСЕГДА** когда задача про **проектирование интерфейса** или **логику интерфейса**.
  Применяется ко всему: новый экран, редизайн, мокап, лендинг, дашборд, навигация, IA, флоу, выбор паттерна, выбор стиля, выбор палитры/типографики, accessibility-чек, ревью существующего UI.
  Запускается **первым** (Step 2: `--design-system` + `--persist` с именем проекта) ещё ДО того как `frontend-design` начнёт писать код.
  Pre-delivery checklist из этого скилла — обязательная часть любой UI-сдачи.
  Зафиксировано 2026-05-26 явно: «должен использовать всегда, когда проектирует интерфейс, как логику интерфейса».

- **`hallmark`** — **ВСЕГДА** для greenfield-страниц (новый лендинг/сайт), redesign, audit существующего UI, или когда нужно достать DNA референса.
  Anti-AI-slop дисциплина: pre-emit self-critique 1-5 по 6 осям (Philosophy, Hierarchy, Execution, Specificity, Restraint, Variety) — если <3 → revision.
  3 явные команды: `hallmark audit <target>` / `hallmark redesign <target>` / `hallmark study <screenshot|URL>`.
  Запускается **после ui-ux-pro-max** (когда design system уже есть) **перед frontend-design** (контроль уникальности).
  Главная задача — заставить вывод выглядеть **структурно** различным от других AI-сгенерённых UI (не просто color-swap шаблона).
  Зафиксировано 2026-05-26: «включить обязательно».

## 🧠 Принципы Гриши (из памяти, не trial-and-error)

Это уже зафиксированные привычки/правила Гриши, проверены на нескольких проектах:

- **Vault first** — ВСЕГДА сначала читать `raw/` и `wiki/` проекта в Obsidian, потом подбирать скилл
- **HTML мокапы → Downloads** (`~/Downloads/<project>-mockups/`), не в vault
- **Без эмодзи в UI** — только SVG-иконки (Lucide/Heroicons)
- **Темная тема стандарт для KDS/admin/кухня**, light для front-of-house (зал/бармен) и web-дашбордов владельца
- **Deliverables не править proactively** — отчёты заказчику не править без явного запроса, Гриша скажет что убирать
- **Meetings vs correspondence** — meetings/ только живые созвоны; чаты и голосовые → correspondence/
